📋 Overview

Slurm (Simple Linux Utility for Resource Management) is an open-source, fault-tolerant, and highly scalable cluster management and job scheduling system for Linux clusters. It performs three key functions: allocating exclusive or non-exclusive access to resources, providing a framework for starting, executing, and monitoring work on allocated nodes, and arbitrating resource contention by managing a queue of pending work.

Section 1: Slurm Architecture & Core Components

ComponentRoleRuns On
slurmctldThe central management daemon. It monitors physical resource state, schedules user queues, and dispatches jobs.Master node only
slurmdThe execution daemon that starts and executes assigned tasks, monitors local node resources, and communicates state back to the controller.Every compute node
mungeThe lightweight authentication service used by Slurm to validate security identities and sign payloads across cluster hosts.All nodes
PartitionsLogical job queue environments grouping nodes into distinct categories with unique constraints (max runtimes, memory boundaries).Defined in slurm.conf

Section 3: Preparing the Slurm Directories

Slurm requires specific file structures for run-time variables, logging messages, and active spool states. Create these on all nodes.

Terminal
Terminal Command 
# Create the Slurm system account
sudo groupadd -r slurm
sudo useradd -r \
  -g slurm \
  -d /var/lib/slurm \
  -s /sbin/nologin \
  -c "Slurm Workload Manager" \
  slurm

# Create required directories
sudo mkdir -p /etc/slurm /var/log/slurm /var/spool/slurm /var/spool/slurmd
sudo chown -R slurm:slurm /etc/slurm /var/log/slurm /var/spool/slurm /var/spool/slurmd

Verify directory parameters and ownership:

Terminal
Terminal Command 
ls -ld /etc/slurm
ls -ld /var/spool/slurm*

Create the Slurm account on all compute nodes in parallel:

Terminal
Terminal Command 
pdsh -R ssh -g compute "sudo groupadd -r slurm || true"
pdsh -R ssh -g compute \
  "sudo useradd -r -g slurm -d /var/lib/slurm -s /sbin/nologin -c 'Slurm Workload Manager' slurm || true"

⚠ Troubleshooting: Directory Owned by Root

Symptom: slurmctld crashes with "Permission denied".
Fix: Run sudo chown slurm:slurm /var/spool/slurm to reassign correct user rights.

4.1 Understanding Configuration Directives

DirectiveDescriptionExample Value

Section 5: Distributing the Configuration

All hosts must share an identical slurm.conf. Use pdcp to distribute files across the compute group:

Terminal
Terminal Command 
pdcp -g compute /etc/slurm/slurm.conf /tmp/slurm.conf
pdsh -R ssh -g compute "sudo cp /tmp/slurm.conf /etc/slurm/slurm.conf"

Confirm configuration integrity by comparing SHA-256 hash outputs:

Terminal
Terminal Command 
pdsh -g compute "sha256sum /etc/slurm/slurm.conf"

✅ Verification

The SHA-256 hashes for compute01–compute04 must exactly match the hash on master. A mismatched hash indicates file corruption or an out-of-sync configuration.

Section 9: Batch Jobs

Batch workloads are non-interactive script processes that run in the background using #SBATCH directives.

9.1 Batch Script Creation

Generate a testing batch script named job.sh on the master node:

Terminal
Terminal Command 
#!/bin/bash
#SBATCH --job-name=HPC_Test
#SBATCH --output=result_%j.out
#SBATCH --nodes=2
#SBATCH --ntasks=2

srun hostname
srun uptime

Understanding the Batch Script

DirectivePurpose
#!/bin/bashShebang — tells Linux to execute with the Bash shell interpreter.
#SBATCH --job-nameAssigns a human-readable name to the job (visible in squeue).
#SBATCH --output=result_%j.outRedirects stdout to a file; %j is replaced by the unique job ID.
#SBATCH --nodes=2Requests two physical/virtual compute nodes for the job.
#SBATCH --ntasks=2Requests two Slurm tasks (processes). Combined with --nodes=2: one task per node.
srun hostnameLaunches the command using Slurm's allocated resources, verifying compute node execution.

9.2 Workload Submission & Queue Verification

Terminal
Terminal Command 
sbatch job.sh
squeue
cat result_*.out

Section 10: Recovering Nodes from DOWN State

During operation, a compute node may enter the DOWN state after a failed job launch, network issue, or daemon restart. Follow this recovery procedure:

Terminal
Terminal Command 
# Step 1: Check the current node state
sinfo

# Step 2: Reset the administrative state
sudo scontrol update NodeName=compute[01-04] State=DOWN Reason="Resetting node state"

# Step 3: Restart slurmd on all compute nodes
pdsh -R ssh -g compute "sudo systemctl restart slurmd"

# Step 4: Return nodes to service
sudo scontrol update NodeName=compute[01-04] State=RESUME

# Step 5: Verify IDLE state
sinfo

Expected result after recovery:

Terminal
Terminal Command 
PARTITION AVAIL  TIMELIMIT  NODES  STATE NODELIST
debug*       up   infinite      4   idle compute[01-04]

Run a final verification across all nodes:

Terminal
Terminal Command 
srun -N1 hostname
srun -N2 hostname
srun -N4 hostname
