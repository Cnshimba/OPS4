OpenMP Shared-Memory Parallelism & Thread Synchronization (Ch. 10 & 11)

1. Foundations of Distributed-Memory Supercomputing

While OpenMP enables shared-memory parallelism across threads inside a single compute node, scaling computational software to thousands of nodes across a supercomputer requires a Distributed-Memory Architecture. In a distributed cluster, each compute node possesses its own private RAM address space. A CPU core on Node A cannot directly dereference a physical memory address residing on Node B.

To coordinate computation, nodes must explicitly exchange data packets over the high-speed network interconnect (InfiniBand / RoCE) using the **Message Passing Interface (MPI)** standard.

2. The Single Program, Multiple Data (SPMD) Model (Chapter 8)

MPI programs execute under the SPMD (Single Program, Multiple Data) model:

  • A single executable binary is launched simultaneously across $N$ distinct processing ranks (instances).
  • Every rank executes the exact same program instructions, but branching statements (if (rank == 0)) allow individual ranks to operate on unique subsets of the global dataset.
  • Ranks are identified by an integer ID ranging from $0toN-1$.

3. MPI Communicators, Ranks & Initialization

Terminal 
#include <mpi.h>
#include <stdio.h>

int main(int argc, char **argv) {
    int rank, world_size;

    // Initialize the MPI execution environment
    MPI_Init(&argc, &argv);

    // Get the process rank ID within the default communicator
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);

    // Get the total number of MPI ranks launched
    MPI_Comm_size(MPI_COMM_WORLD, &world_size);

    printf("Hello from MPI Rank %d of %d\n", rank, world_size);

    // Finalize the MPI environment
    MPI_Finalize();
    return 0;
}

4. Point-to-Point Communication Mechanics

Point-to-point communication transfers data explicitly from one sender rank to one receiver rank:

4.1 Synchronous / Blocking Point-to-Point (MPI_Send & MPI_Recv)

Terminal 
// Rank 0 sends 100 doubles to Rank 1
if (rank == 0) {
    MPI_Send(data_buffer, 100, MPI_DOUBLE, 1, 99, MPI_COMM_WORLD);
} else if (rank == 1) {
    MPI_Recv(data_buffer, 100, MPI_DOUBLE, 0, 99, MPI_COMM_WORLD, MPI_STATUS_IGNORE);
}

4.2 Asynchronous / Non-Blocking Point-to-Point (MPI_Isend & MPI_Irecv)

Non-blocking calls initiate communication and return control immediately to the CPU, allowing computation and network transmission to overlap seamlessly:

Terminal 
MPI_Request request;
// Non-blocking send initiation
MPI_Isend(send_buf, 100, MPI_DOUBLE, neighbor_rank, 0, MPI_COMM_WORLD, &request);

// Perform local computation while network transfers payload
compute_local_interior_grid();

// Wait for non-blocking communication to complete
MPI_Wait(&request, MPI_STATUS_IGNORE);

5. Collective Communications

Collective operations involve all ranks within a communicator simultaneously:

Collective FunctionData Movement PatternScientific Use Case
MPI_BcastOne rank broadcasts a buffer to all other ranks.Distributing global simulation configuration parameters.
MPI_ScatterSplits a root array into equal chunks and distributes one chunk to each rank.Distributing input matrix rows across worker ranks.
MPI_GatherCollects equal data chunks from all ranks into a single array on the root rank.Gathering sub-grid results for centralized disk I/O.
MPI_ReduceCombines data from all ranks using a mathematical operator (MPI_SUM, MPI_MAX).Computing global kinetic energy sums across ranks.
MPI_AllreduceCombines data using an operator and distributes the final result to all ranks.Global residual error checks in iterative solvers.
MPI_BarrierSynchronizes all ranks; blocks execution until every rank enters the barrier.Debugging phase boundaries and timing benchmarks.

6. Python MPI Programming with mpi4py

High-level Python scientific software utilizes mpi4py to bind to native OpenMPI/MPICH C libraries:

Terminal 
from mpi4py import MPI
import numpy as np

comm = MPI.COMM_WORLD
rank = comm.Get_rank()
size = comm.Get_size()

# Fast NumPy direct buffer communication (capitalized API)
if rank == 0:
    data = np.arange(1000000, dtype=np.float64)
else:
    data = np.empty(1000000, dtype=np.float64)

# Broadcast NumPy array directly via RDMA
comm.Bcast(data, root=0)
print(f"Rank {rank} received array sum: {np.sum(data)}")

7. Hybrid Parallelism Setup (MPI + OpenMP)

At modern supercomputer scale, pure MPI places an independent process on every single core, resulting in excessive MPI communicator overhead and memory footprint duplicated across cores on the same node. The standard enterprise pattern is Hybrid MPI+OpenMP Parallelism:

  • MPI Layer: Spawns **1 MPI Rank per NUMA Socket** (e.g., 2 ranks per node) to manage inter-node network communication over InfiniBand.
  • OpenMP Layer: Each MPI rank spawns an **OpenMP Thread Team** (e.g., 8–16 threads) to exploit intra-socket shared RAM without network copying.
Terminal 
#include <mpi.h>
#include <omp.h>
#include <stdio.h>

int main(int argc, char **argv) {
    int provided_thread_support;
    // Request MPI thread support level for hybrid execution
    MPI_Init_thread(&argc, &argv, MPI_THREAD_FUNNELED, &provided_thread_support);

    int rank;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);

    #pragma omp parallel
    {
        int thread_id = omp_get_thread_num();
        printf("MPI Rank %d | OpenMP Thread %d executing in hybrid mode\n", rank, thread_id);
    }

    MPI_Finalize();
    return 0;
}
