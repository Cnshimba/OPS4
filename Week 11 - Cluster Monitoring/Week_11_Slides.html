Week 11 Slides: Cluster Monitoring

Slide 1: System Administration (Chapter 13)

  • Role: Ensuring the cluster provides value to science.
  • RAS Goals:
    • Reliability: Accuracy of results.
    • Availability: Uptime (Target 99% - 99.999%).
    • Serviceability: Ease of repair.
  • The Cycle: Install -> Configure -> Operate -> Decommission.
  • Key Task: You cannot manage what you do not measure.

Slide 2: Why Monitor?

  • The Problem: You have 100 computers. One is slow. Which one?
  • The Old Way (Logging): Checking /var/log/messages on 100 nodes.
  • The New Way (Metrics): A dashboard showing CPU load for the whole rack at once.
  • Observability: Knowing why it broke, not just that it broke.

Slide 3: Push vs. Pull

  • Push (Agents send data):
    • Example: Ganglia, Nagios.
    • Risk: DDoS Attack. If all nodes wake up and scream at the Master, the Master dies.
  • Pull (Server scrapes data):
    • Example: Prometheus.
    • Safety: The Master decides when to ask for data. It stays in control.

Slide 4: The Stack

  • 1. Node Exporter:
    • Runs on Compute Nodes.
    • Converts /proc/meminfo into HTTP text.
  • 2. Prometheus:
    • The Database.
    • Visits http://node:9100/metrics every 15s.
    • Stores the numbers.
  • 3. Grafana:
    • The Face.
    • Queries Prometheus.
    • Draws the lines/bars/gauges.

Slide 4: Anomalies

  • Pattern Recognition: Humans are bad at reading CSV files. Humans are great at spotting a dip in a line graph.
  • Heterogeneity:
    • Node 1-3: 10% Load.
    • Node 4: 99% Load.
    • Result: Node 4 is likely a "Straggler" or stuck job.

Slide 5: Lab Overview

  • Goal: Build the full stack.
  • Steps:
    1. Install node_exporter on compute image.
    2. Install prometheus on Master.
    3. Install grafana on Master.
    4. Connect them and see the heartbeat of your cluster.
