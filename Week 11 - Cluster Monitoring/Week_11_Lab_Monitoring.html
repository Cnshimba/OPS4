📋 Overview

A critical bottleneck in massive supercomputers is storage I/O throughput. Traditional NFS operates on a centralised client-server paradigm that serialises writes under parallel load. Parallel Filesystems (Lustre, GPFS) solve this by decoupling metadata from raw block writes and distributing data blocks dynamically across isolated storage servers — enabling linear I/O scaling as storage drives are added.

Section 2: Lustre Architecture and Components

Lustre is the primary storage system of the world's fastest supercomputers. Understanding its components is essential for parallel systems administrators:

ComponentAcronymFunction
Metadata ServerMDSManages directory paths, filenames, active permissions, and file layouts
Metadata TargetMDTThe physical storage media (e.g., NVMe SSD arrays) attached to the MDS that stores the metadata structure
Object Storage ServerOSSThe storage servers that manage raw file data blocks
Object Storage TargetOSTThe physical disk drives (e.g., HDD arrays or SSD pools) attached to the OSS that store block objects

2.1 Lustre File Striping

Lustre uses file striping to maximise write bandwidth. When a file is written, Lustre breaks it into equal-sized chunks and writes them across multiple OSTs simultaneously:

  • Stripe Count: The number of OSTs across which a single file is segmented and written in parallel.
  • Stripe Size: The size of each data chunk (default is typically 1 Megabyte).

Section 3: Integrating Parallel I/O with MPI-IO

In Lab 6 (HPC Software Stack), you compiled Parallel HDF5 using MPI compiler wrappers. HDF5 uses the MPI-IO interface to execute collective write operations. Instead of nodes performing independent random writes, the MPI collective I/O layer reorganises data write blocks in RAM, executing long sequential streaming write sweeps to the parallel filesystem's OSTs — bypassing metadata lock contention.

📌 POSIX File Interface

The POSIX file interface (open, read, write, close, seek) was designed for single-process access. Its strict consistency model becomes a bottleneck when thousands of MPI ranks attempt concurrent writes to the same file. MPI-IO and parallel filesystems extend POSIX semantics with collective I/O operations optimised for distributed workloads.

Section 4: Storage Throughput Testing

Exercise 1 – Measure NFS Sequential Write Bandwidth

Using the dd command, execute a 1 GB sequential write on the /shared NFS mount. The oflag=direct flag bypasses the OS page cache, forcing direct writes to disk media:

Terminal
Terminal Command 
dd if=/dev/zero of=/shared/test_io.img bs=1M count=1024 oflag=direct

Note the returned write bandwidth speed (e.g., 22.4 MB/s). This bottleneck represents the network latency and serialisation overhead of NFS over a single socket.

Exercise 2 – Measure Local Disk Write Bandwidth

Repeat the transaction on a local node directory:

Terminal
Terminal Command 
dd if=/dev/zero of=/tmp/test_io.img bs=1M count=1024 oflag=direct

Observe how local disk bandwidth is significantly faster (e.g., 120 MB/s) because it does not traverse the NFS socket layer.

Exercise 3 – Running Parallel I/O Benchmarks (IOR)

Scientists use the IOR (Interleaved Or Random) benchmark to test distributed parallel write throughput. Submit an IOR parallel sweep across all 4 compute nodes via Slurm:

Terminal Command 
srun -N 4 -n 4 /shared/benchmarks/ior/ior \

Section 5: Lustre Administrative Commands

On a production Lustre system, administrators use these commands to manage and tune storage:

Terminal
Terminal Command 
# Check OST disk space distribution
lfs df -h

# Check file striping for a specific file
lfs getstripe /lustre/scratch/myfile.h5

# Set striping for a new directory (4 OSTs, 4 MB stripe size)
lfs setstripe -c 4 -S 4M /lustre/scratch/myproject/

# List available OSTs
lfs osts

# Check Lustre client mount status
lctl get_param llite.*.stats

Section 6: Troubleshooting Storage Bottlenecks

SymptomPossible CauseResolution
I/O error: disk quota exceededOne or more OSTs have run out of physical block space, even though other OSTs remain empty.Check OST capacity with lfs df -h. Adjust file striping with lfs setstripe to balance blocks across other targets.
Extreme file creation delays (Metadata lock timeout)The MDS is bottlenecked due to thousands of parallel processes creating tiny files concurrently.Rewrite application to write large sequential arrays within consolidated HDF5 containers rather than millions of small files.
Write bandwidth drops during MPI runsData blocks are unaligned with the underlying parallel filesystem stripe size, triggering heavy write lock contention.Ensure MPI-IO transfer alignment matches the Lustre stripe size. Configure HDF5: H5Pset_alignment().
NFS mount hangs under heavy parallel loadSingle NFS server socket is saturated by concurrent write requests from all compute nodes.Reduce concurrency, or migrate large scratch workloads to a parallel filesystem (Lustre/BeeGFS).
