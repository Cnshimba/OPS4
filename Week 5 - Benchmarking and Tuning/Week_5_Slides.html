Week 7 Slides: HPC Benchmarking and Tuning

Slide 1: Introduction to Benchmarking

  • The Question: "How fast is my cluster?"
  • The Problem: "Fast" is subjective.
  • The Solution: Standardized Metrics.
    • FLOPs: Compute Speed (Math).
    • Bandwidth: Data Movement Speed (Memory/Network).
    • Latency: Delay/Wait time.

Slide 2: The Memory Wall

  • CPU Limitation: CPUs get faster every year (Moore's Law).
  • Memory Limitation: RAM speed grows much slower.
  • The Gap: The "Von Neumann Bottleneck".
  • Result: Most HPC codes are waiting for data, not calculating.
    • Compute-Bound: Limited by math (Rare).
    • Memory-Bound: Limited by data fetch (Common).

Slide 3: The Roofline Model

  • Visualizing Performance:
    • X-Axis: Arithmetic Intensity (Math operations per Byte).
    • Y-Axis: Performance (GFLOPS).
  • The Roofs:
    • Flat Roof: Peak CPU Speed.
    • Slanted Roof: Peak Memory Bandwidth.
  • Goal: Move your code UP (optimize) or RIGHT (increase intensity).

Slide 4: HPL (High Performance Linpack)

  • The Standard: Used for the TOP500 list.
  • The Math: Solves $Ax = b$ (Dense Linear Algebra).
  • Characteristics:
    • $O(N^3)$ Ops on $O(N^2)$ Data.
    • Very High Arithmetic Intensity.
    • Compute-Bound: Hits the "Flat Roof".
  • Tuning: Adjust N (Size), NB (Block Size), P x Q (Grid).

Slide 5: STREAM Benchmark

  • The Reality Check: HPL is unrealistic for many apps.
  • The Metric: Sustained Memory Bandwidth (GB/s).
  • Operations:
    1. Copy: a = b
    2. Scale: a = q*b
    3. Add: a = b + c
    4. Triad: a = b + q*c (Most important).

Slide 6: Tuning Fundamentals

  • Free Speed: Don't rewrite code immediately.
  • Compiler Flags:
    • -O0: Debug (Slow).
    • -O3: Production (Fast).
    • -march=native: Use this CPU's special instructions (AVX).
  • Libraries:
    • Use BLAS/LAPACK (MKL, OpenBLAS).
    • Never write your own Matrix Multiply!

Slide 7: Lab Overview

  • Tasks:
    1. Compiler Test: Measure time of -O0 vs -O3.
    2. Run STREAM: Find the memory limit of a node.
    3. Run HPL: Find the GFLOPS limit of the cluster.
