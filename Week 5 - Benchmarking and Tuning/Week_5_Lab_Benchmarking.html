Week 5: Benchmarking and Tuning - Lab Guide

HPC & Cluster Computing

Objective: Characterize the performance of your cluster using standard benchmarks. Goal: Measure Memory Bandwidth (STREAM) and Compute Performance (HPL), and observe the effect of compiler flags.

1. The Impact of Compiler Optimizations

Before running complex benchmarks, let's see how much "free" speed we can get just by asking the compiler to work harder.

1.1 Create the Test Code

Create a file named matrix_test.c. This code simply multiplies two matrices.

#include <stdio.h>
#include <stdlib.h>
#include <time.h>

#define N 1000

int main() {
    double *A = malloc(N * N * sizeof(double));
    double *B = malloc(N * N * sizeof(double));
    double *C = malloc(N * N * sizeof(double));

    // Initialize
    for(int i=0; i<N*N; i++) { A[i] = 1.0; B[i] = 2.0; }

    clock_t start = clock();

    // Multiply
    for(int i=0; i<N; i++) {
        for(int j=0; j<N; j++) {
            for(int k=0; k<N; k++) {
                C[i*N+j] += A[i*N+k] * B[k*N+j];
            }
        }
    }

    clock_t end = clock();
    printf("Time: %f seconds\n", (double)(end - start) / CLOCKS_PER_SEC);
    return 0;
}

1.2 Compile and Compare

  1. Compile with No Optimization (-O0): bash gcc -O0 matrix_test.c -o matrix_slow ./matrix_slow Record the time.

  2. Compile with Aggressive Optimization (-O3): bash gcc -O3 matrix_test.c -o matrix_fast ./matrix_fast Record the time.

Result: You should see a drastic difference (often 10x or more) just from flags.

2. STREAM Benchmark (Memory Bandwidth)

We will use the STREAM benchmark to find the peak memory bandwidth of a single node.

2.1 Download and Compile

  1. Download the source: bash wget https://www.cs.virginia.edu/stream/FTP/Code/stream.c
  2. Compile with OpenMP support (to use all memory channels): bash gcc -O3 -fopenmp -DSTREAM_ARRAY_SIZE=10000000 stream.c -o stream

2.2 Run the Benchmark

Run it on a single node (e.g., inside an srun --pty bash session):

export OMP_NUM_THREADS=4  # Match your Core count
./stream

Analyze: Look at the "Copy" and "Triad" values. Result: ______ MB/s

3. HPL (High Performance Linpack)

Now we measure the Peak Flops of the cluster.

3.1 Install HPL

Building HPL from source is complex (requires BLAS, MPI). For this lab, we will use a standard container or package if available, or a simplified build. Assumption: hpl is installed in the environment (e.g., dnf install hpl or via Spack). If not, download a pre-compiled binary provided by the instructor.

3.3 Run on 1 Node

Run HPL on a single core (Serial):

mpirun -np 1 ./xhpl
  • Look for the final result: Gflops.

3.4 Run on 2 Nodes (Parallel)

  1. Edit HPL.dat: Change Ps to 2 and Qs to 1 (Total 2 processes).
  2. Increase Ns to 8000 (More nodes = more RAM = bigger problem).
  3. Submit via Slurm: bash srun -N 2 --ntasks-per-node=1 ./xhpl

Goal: Did your Gflops double? If not, why? (Network latency, small problem size?)
