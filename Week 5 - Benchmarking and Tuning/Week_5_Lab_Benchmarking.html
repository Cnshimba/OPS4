Section 1: Lab Overview & Architectural Goals

1.1 The Fork-Join Execution Model

PhaseDescription
Master Thread (Sequential)The program begins as a single thread. It executes sequentially until it encounters an OpenMP #pragma omp parallel directive.
Fork (Parallel Regions)The Master thread forks (creates) a team of concurrent worker threads. Each thread executes instructions simultaneously.
Join (Synchronisation)At the end of the parallel block, a barrier synchronisation is implicitly enforced. Worker threads terminate, leaving only the master to resume sequential execution.

1.2 Flynn's Architecture Taxonomy

ClassDescriptionExample
SISDSingle Instruction Single Data — standard single-threaded processors.Sequential C programs
SIMDSingle Instruction Multiple Data — vector processors executing one instruction across a data vector.CPU vectorisation, AVX
MIMDMultiple Instruction Multiple Data — multi-core computers executing independent processor streams over different datasets. OpenMP and MPI are primary software examples.OpenMP, MPI, GPU compute

#include <stdio.h>

int main() {

    #pragma omp parallel
    {

        int total_threads = omp_get_num_threads();

Section 4: Exercise 2 – Parallel Loop Worksharing

Create /shared/omp_vector_add.c:

Terminal
Terminal Command 
#include <omp.h>
#include <stdio.h>
#define N 10000000
float a[N], b[N], c[N];

int main() {
    for (int i = 0; i < N; i++) { a[i] = 1.0f; b[i] = 2.0f; }

    double start_time = omp_get_wtime();

    // Parallelize the loop using worksharing directives
    #pragma omp parallel for
    for (int i = 0; i < N; i++) {
        c[i] = a[i] + b[i];
    }

    double end_time = omp_get_wtime();
    printf("Vector addition completed in %.6f seconds\n", end_time - start_time);
    return 0;
}
Terminal
Terminal Command 
gcc -O2 -fopenmp /shared/omp_vector_add.c -o /shared/omp_vector_add
/shared/omp_vector_add

📌 OpenMP Loop Scheduling

  • static: Pre-allocates iterations evenly to each thread before execution (ideal for balanced loops).
  • dynamic: Allocates chunks of iterations dynamically at runtime as threads become idle (ideal for unbalanced workloads).
  • guided: Iteratively decreases chunk sizes to optimise tail latency.

Section 6: Exercise 4 – Thread Reductions vs Critical Sections

Create /shared/omp_reduction.c:

Terminal
Terminal Command 
#include <omp.h>
#include <stdio.h>
#define N 1000000

int main() {
    double sum_race = 0.0, sum_critical = 0.0, sum_reduction = 0.0;

    // 1. DATA RACE (INCORRECT - demonstrates the problem)
    #pragma omp parallel for
    for (int i = 1; i <= N; i++) { sum_race += 1.0; }

    // 2. CRITICAL SECTION (CORRECT BUT SLOW)
    #pragma omp parallel for
    for (int i = 1; i <= N; i++) {
        #pragma omp critical
        { sum_critical += 1.0; }
    }

    // 3. REDUCTION DIRECTIVE (CORRECT AND FAST)
    #pragma omp parallel for reduction(+:sum_reduction)
    for (int i = 1; i <= N; i++) { sum_reduction += 1.0; }

    printf("Race Sum      : %.1f (Expected: %d.0)\n", sum_race, N);
    printf("Critical Sum  : %.1f (Expected: %d.0)\n", sum_critical, N);
    printf("Reduction Sum : %.1f (Expected: %d.0)\n", sum_reduction, N);
    return 0;
}
Terminal
Terminal Command 
gcc -fopenmp /shared/omp_reduction.c -o /shared/omp_reduction
/shared/omp_reduction

⭐ Core Concept: Reductions are Highly Optimised

The critical directive locks the sum variable across threads, causing execution to bottleneck. In contrast, the reduction(+:variable) clause allocates a local copy per thread, accumulating loop iterations in parallel before performing a highly optimised global merge at the join synchronisation barrier.

Section 7: Exercise 5 – OpenMP Matrix Multiplication & Dynamic Scheduling

In this exercise, you will parallelise a 2D matrix multiplication kernel using the OpenMP collapse(2) clause and compare performance between static and dynamic loop schedules.

Create /shared/omp_matrix.c:

Terminal
Terminal Command 
#include <omp.h>
#include <stdio.h>
#include <stdlib.h>

#define N 500

double A[N][N], B[N][N], C[N][N];

int main() {
    // Initialize matrices
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < N; j++) {
            A[i][j] = 1.0;
            B[i][j] = 2.0;
            C[i][j] = 0.0;
        }
    }

    double start = omp_get_wtime();

    // Collapse outer 2 loops into a single parallel iteration space
    #pragma omp parallel for collapse(2) schedule(dynamic, 16)
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < N; j++) {
            double sum = 0.0;
            for (int k = 0; k < N; k++) {
                sum += A[i][k] * B[k][j];
            }
            C[i][j] = sum;
        }
    }

    double end = omp_get_wtime();
    printf("Parallel Matrix Multiplication (%dx%d) completed in %.4f seconds\n", N, N, end - start);
    return 0;
}

Compile and Test Execution

Terminal
Terminal Command

export OMP_NUM_THREADS=4
/shared/omp_matrix

Thread counts revert to 1OMP_NUM_THREADS not defined, or compiled without -fopenmp.Verify compilation contains -fopenmp. Run export OMP_NUM_THREADS=4.
Segmentation Fault inside parallel regionsStack overflow: thread private variables exceeded allocation limits.Run export OMP_STACKSIZE=16M or allocate on heap using malloc.
Sum variable values are unpredictableRace condition: multiple threads writing to shared sum variable.Use #pragma omp critical or the reduction clause.
