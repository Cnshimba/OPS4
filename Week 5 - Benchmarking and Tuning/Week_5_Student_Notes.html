1. Foundations of Shared-Memory Programming

Having explored multi-core SMP and NUMA hardware mechanics in Week 4, we now examine software engineering methodologies for parallelizing code across shared-memory CPUs. OpenMP (Open Multi-Processing) is the multi-vendor industry standard API for shared-memory multithreading in C, C++, and Fortran.

Unlike explicit low-level threading libraries (such as POSIX Threads / Pthreads), which require manual thread creation, stack management, mutex locking, and joins, OpenMP uses high-level, compiler-directed annotations (pragmas) to incrementally convert sequential programs into multithreaded applications.

2. The Fork-Join Execution Model (Chapter 7)

OpenMP execution strictly follows the Fork-Join Execution Model:

  1. Sequential Execution (Master Thread): The application begins as a single sequential thread (Thread ID 0).
  2. Forking Phase: When the master thread encounters an OpenMP parallel directive (e.g., #pragma omp parallel), it forks a team of worker threads.
  3. Parallel Work Execution: Statements inside the parallel region are executed concurrently by all threads in the team.
  4. Implicit Barrier & Join Phase: At the closing brace of the parallel region, worker threads synchronize at an implicit barrier and join back into the single master thread.

3. Core Directives & Worksharing Constructs

3.1 Parallel Region Construct

Terminal 
#include <omp.h>
#include <stdio.h>

int main() {
    // Programmatically set worker thread count
    omp_set_num_threads(4);

    #pragma omp parallel
    {
        int tid = omp_get_thread_num();
        int num_threads = omp_get_num_threads();
        printf("Hello from OpenMP Thread %d of %d\n", tid, num_threads);
    }
    return 0;
}

3.2 Loop Worksharing Construct (#pragma omp parallel for)

In scientific computing, loop worksharing is the most frequent parallelization technique:

Terminal 
#define N 10000000
double a[N], b[N], c[N];

// Parallelize loop iterations across the thread team
#pragma omp parallel for schedule(static)
for (int i = 0; i < N; i++) {
    c[i] = a[i] + b[i];
}

4. Data Scoping & Variable Memory Rules

Because all OpenMP threads access the same physical memory space, programmers must explicitly declare variable scoping rules:

Scoping ClauseMemory Allocation RuleTypical Scientific Application
shared(var)Single memory address shared across all threads. Default for pre-existing variables.Read-only input arrays, global configuration matrices.
private(var)Each thread allocates an uninitialized local copy on its private stack. Original variable is unchanged.Loop index variables (i, j), temporary local registers.
firstprivate(var)Each thread allocates a local copy initialized with the master thread's pre-region value.Constant scale parameters needed in local calculations.
lastprivate(var)The thread executing the final logical loop iteration copies its value back to the master variable.Tracking the last computed state after loop exit.

5. Race Conditions, Reductions & Synchronization

5.1 Data Race Conditions

A **Data Race Condition** occurs when two or more threads attempt to read and write to the same shared memory location simultaneously without synchronization. Data races produce non-deterministic calculations.

5.2 Reduction Clause

To safely compute global sums, products, or min/max values without race conditions or lock overhead, OpenMP provides reductions. Each thread accumulates into a private accumulator, which is combined at the join barrier:

Terminal 
double global_pi_sum = 0.0;
double h = 1.0 / (double)N;

#pragma omp parallel for reduction(+:global_pi_sum) private(x)
for (int i = 0; i < N; i++) {
    double x = (i + 0.5) * h;
    global_pi_sum += 4.0 / (1.0 + x * x);
}
double pi = global_pi_sum * h;

5.3 Synchronization Constructs

ConstructSyntaxBehavior & Performance Impact
Critical Section#pragma omp criticalSerializes thread execution. Only one thread executes the block at a time. High overhead.
Atomic Update#pragma omp atomicLeverages CPU hardware atomic instructions for single memory updates (x += 1). Low overhead.
Barrier#pragma omp barrierForces all threads to pause until every thread arrives at the barrier point.
Single Execution#pragma omp singleEnforces that only one thread in the team executes the block (ideal for I/O calls).

6. OpenMP Loop Scheduling Strategies

Schedule TypeSyntax ExampleAlgorithmic Behavior & Workload Fit
Staticschedule(static, 64)Divides loop iterations into fixed chunks assigned round-robin at loop start. Lowest overhead; ideal for balanced regular loops.
Dynamicschedule(dynamic, 16)Threads grab chunk allocations dynamically from a shared queue when idle. Higher overhead; ideal for irregular/unbalanced workloads.
Guidedschedule(guided, 16)Chunk size starts large and decreases exponentially to balance load while minimizing queue contention.

7. Environmental Controls & Thread Affinity

Terminal 
# Set environment thread count
export OMP_NUM_THREADS=16

# Configure loop scheduling policy externally
export OMP_SCHEDULE="guided,32"

# Bind OpenMP threads to physical CPU cores (prevents cross-NUMA migration)
export OMP_PROC_BIND=close
export OMP_PLACES=cores

# Set stack size limit for OpenMP threads
export OMP_STACKSIZE=64M
