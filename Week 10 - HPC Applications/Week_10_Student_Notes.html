1. Evolutionary Rationale & History of Accelerators (Chapter 15)

Modern supercomputers achieve over 90% of their theoretical floating-point capability using **Heterogeneous Computing Architectures**. A heterogeneous supercomputer pairs latency-optimized multi-core CPUs (Hosts) with throughput-optimized Graphics Processing Units (Devices) containing thousands of smaller arithmetic processing units.

  1. Early Math Coprocessors (1970s–1980s): Offloaded floating-point math instructions from legacy CPUs over a slow system bus.
  2. General-Purpose GPUs (GPGPU - 2000s to Present): Evolved graphics rasterization pipelines into programmable parallel compute engines connected via PCIe Gen5 x16 slots or custom high-speed NVLink interconnects.

2. Host (CPU) vs. Device (GPU) Architectural Model

Architectural MetricCPU (Host)GPU (Device Accelerator)
Core Count & Logic16 to 128 large cores with complex branch prediction & out-of-order execution logic.2,000 to 18,000+ smaller SIMD cores dedicated strictly to arithmetic calculations.
Execution ModelMIMD (Multiple Instruction, Multiple Data).SIMT (Single Instruction, Multiple Threads) in 32-thread Warps.
Memory SubsystemSystem DDR5 RAM (~100–300 GB/s bandwidth).High Bandwidth Memory (HBM3) (~2,000 to 3,300 GB/s bandwidth).
Latency vs ThroughputOptimized for low single-thread instruction latency.Optimized for massive parallel FLOP throughput.

3. The NVIDIA CUDA SIMT Execution Model

CUDA exposes a 3-tier logical thread hierarchy:

  1. Thread: The individual execution path on a CUDA core.
  2. Thread Block: A group of up to 1024 threads scheduled together on a single **Streaming Multiprocessor (SM)**. Threads in a block share ultra-fast **Shared Memory** (L1 speed) and barrier synchronization (__syncthreads()).
  3. Grid: A 1D, 2D, or 3D array of thread blocks executing the exact same kernel function.

3.1 Complete CUDA C/C++ Vector Addition Code Walkthrough

Terminal 
#include <stdio.h>
#include <cuda_runtime.h>

// CUDA Kernel function executing on Device (GPU)
__global__ void vectorAddKernel(const float *A, const float *B, float *C, int N) {
    // Calculate global 1D thread index
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < N) {
        C[i] = A[i] + B[i];
    }
}

int main() {
    int N = 1 << 20; // 1,048,576 elements
    size_t bytes = N * sizeof(float);

    // Allocate Host memory
    float *h_A = (float*)malloc(bytes);
    float *h_B = (float*)malloc(bytes);
    float *h_C = (float*)malloc(bytes);

    // Allocate Device memory on GPU
    float *d_A, *d_B, *d_C;
    cudaMalloc(&d_A, bytes);
    cudaMalloc(&d_B, bytes);
    cudaMalloc(&d_C, bytes);

    // Transfer input data from Host RAM to Device HBM over PCIe
    cudaMemcpy(d_A, h_A, bytes, cudaMemcpyHostToDevice);
    cudaMemcpy(d_B, h_B, bytes, cudaMemcpyHostToDevice);

    // Configure grid: 256 threads per block
    int threadsPerBlock = 256;
    int blocksPerGrid = (N + threadsPerBlock - 1) / threadsPerBlock;

    // Launch CUDA kernel on GPU
    vectorAddKernel<<>>(d_A, d_B, d_C, N);

    // Copy result back from Device HBM to Host RAM
    cudaMemcpy(h_C, d_C, bytes, cudaMemcpyDeviceToHost);

    // Free memory allocations
    cudaFree(d_A); cudaFree(d_B); cudaFree(d_C);
    free(h_A); free(h_B); free(h_C);
    return 0;
}

4. Directive-Based GPU Offloading (OpenACC & OpenMP 5 - Chapter 16)

While low-level CUDA provides maximum hardware control, OpenACC and OpenMP 5 Target Offload allow scientific developers to parallelize existing code using pragma directives without rewriting algorithms in CUDA:

Terminal 
// OpenACC Loop Directives
#pragma acc data copyin(a[0:N], b[0:N]) copyout(c[0:N])
{
    #pragma acc parallel loop
    for (int i = 0; i < N; i++) {
        c[i] = a[i] + b[i];
    }
}

// OpenMP 5 Target Offload Directives
#pragma omp target teams distribute parallel for map(to: a[0:N], b[0:N]) map(from: c[0:N])
for (int i = 0; i < N; i++) {
    c[i] = a[i] + b[i];
}
