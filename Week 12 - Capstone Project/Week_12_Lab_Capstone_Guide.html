1. Executive Summary & Project Mission

The Capstone Project represents the practical pinnacle of the Operating Systems 4 (EIOPS4A) curriculum. Working collaboratively in groups of two (2), students demonstrate the ability to transform a raw High-Performance Computing infrastructure into a production-grade, optimized scientific computing platform.

To reflect real-world supercomputing workflows, your group is provided with a fully functional starting infrastructure consisting of a 5-node Rocky Linux 9 cluster where private networking, shared NFS storage, Munge security authentication, the Slurm Workload Manager, and base Open MPI are already active. Your team's mission is to:

  1. Verify the starting foundation (Labs 1, 2, 3) ensuring multi-node communication, scheduler health, and shared storage.
  2. Build and configure the complete scientific software stack (Lab 4) natively from source under /shared/apps/ and register each library with dynamic Lmod Lua environment modules under /shared/modulefiles/.
  3. Deploy a centralized Python HPC environment (Lab 4) linked dynamically to custom OpenBLAS and fully configure mpi4python (mpi4py) for distributed Python execution.
  4. Conduct cluster benchmarking and performance tuning (Lab 6) using High-Performance Linpack (HPL), calculating theoretical Rpeak, extracting sustained Rmax, and evaluating cluster efficiency.
  5. Master distributed-memory MPI parallel programming (Chapter 8 Workbook) covering point-to-point, synchronization barriers, and collective communication primitives.
  6. Successfully defend your deployment in a live demonstration: During the scheduled group assessment, the lecturer will inspect your cluster and hand your team an unannounced test algorithm based on any of the installed libraries. Your group must compile, submit via Slurm, execute across worker nodes, and explain the parallel execution live on the spot!

👥 Group Collaboration Policy

This capstone must be executed in pairs (groups of two). Both partners are expected to contribute equally to the library compilation, Lmod configuration, benchmarking, and code execution. During the live demonstration, each student will undergo an individual oral examination to defend specific architectural aspects of the cluster.

2. Covered Laboratory Units & Technical Scope

This capstone project synthesizes competencies exclusively from the following six curriculum modules:

Lab 1 & Lab 2: Infrastructure & Slurm

Baseline Provided

5-node Rocky Linux 9.6 topology (master + compute01-04), Chrony time sync, private subnet 192.168.56.0/24, NFS /shared export, Munge key authentication, and Slurm scheduler (slurmctld, slurmd) in active IDLE state.

Lab 3: Open MPI & PMIx Integration

Baseline Provided

Open MPI 4.1.x runtime and mpicc compiler wrappers integrated with Slurm via Process Management Interface Exascale (PMIx). Validated multi-node job dispatch using srun and sbatch.

Lab 4: The Scientific Software Stack

Core Student Task

Source compilation of OpenBLAS (OpenMP, dynamic architecture), FFTW 3 (MPI enabled), Parallel HDF5 (MPI-IO), ScaLAPACK (CMake, OpenBLAS-linked), and PETSc. Lmod modulefiles and centralized Python with mpi4python.

Lab 6: Cluster Benchmarking (HPL)

Core Student Task

Source compilation of High-Performance Linpack (xhpl) linked to custom OpenBLAS and Open MPI. Memory sizing of N in HPL.dat, process grid tuning (P × Q = 8), Slurm batch execution, and calculation of Rpeak, Rmax, and efficiency E.

Chapter 8 Workbook: Distributed-Memory MPI Programming

Core Student Task & Demo Foundation

Mastery of MPI communication paradigms: Point-to-point (MPI_Send/MPI_Recv), synchronization barriers (MPI_Barrier), host querying (MPI_Get_processor_name), collective distributions (MPI_Bcast, MPI_Scatter, MPI_Gather, MPI_Allgather), parallel reductions (MPI_Reduce with MPI_SUM, MPI_MIN, MPI_MAX), and end-to-end multi-stage distributed algorithms.

4. Student Implementation Requirements (Lab 4, Lab 6 & Ch 8)

Your group must build the following components on the shared storage volume (/shared/apps/ and /shared/modulefiles/) so that they immediately propagate to all compute nodes:

4.1 Milestone 1: Compiling the Scientific Software Stack (Lab 4)

All software must be compiled natively from source using appropriate compiler optimization flags and parallel MPI wrappers:

1. OpenBLAS (v0.3.26)

/shared/apps/openblas

Optimized BLAS & LAPACK linear algebra kernels. Must be compiled with dynamic CPU architecture detection and OpenMP multi-threading support:

cd /workspace/scratch/OpenBLAS-0.3.26
make -j2 DYNAMIC_ARCH=1 USE_OPENMP=1
make PREFIX=/shared/apps/openblas install

2. FFTW 3 (v3.3.10)

/shared/apps/fftw3

Fastest Fourier Transform in the West. Must be configured with shared libraries and distributed MPI support enabled:

cd /workspace/scratch/fftw-3.3.10
module load mpi/openmpi-x86_64
./configure --enable-shared --enable-mpi --prefix=/shared/apps/fftw3
make -j2 && make install

3. Parallel HDF5 (v1.14.3)

/shared/apps/hdf5

Hierarchical scientific data format. Must be compiled with MPI compiler wrappers (CC=mpicc) to activate parallel MPI-IO collective writing:

cd /workspace/scratch/hdf5-hdf5_1.14.3
CC=mpicc ./configure --enable-parallel --enable-shared --prefix=/shared/apps/hdf5
make -j2 && make install

4. ScaLAPACK (v2.2.0)

/shared/apps/scalapack

Scalable Linear Algebra Package for distributed-memory architectures. Built using CMake, explicitly linking against your custom OpenBLAS:

cd /workspace/scratch/scalapack-2.2.0/build
cmake .. -DCMAKE_INSTALL_PREFIX=/shared/apps/scalapack \
         -DBUILD_SHARED_LIBS=ON \
         -DLAPACK_LIBRARIES=/shared/apps/openblas/lib/libopenblas.so \
         -DBLAS_LIBRARIES=/shared/apps/openblas/lib/libopenblas.so
make -j2 && make install

5. PETSc (v3.20.5)

/shared/apps/petsc

Portable, Extensible Toolkit for Scientific Computation. Integrates MPI, OpenBLAS, ScaLAPACK, and HDF5 into a unified solver engine:

cd /workspace/scratch/petsc-3.20.5
./configure --prefix=/shared/apps/petsc \
            --with-cc=mpicc --with-cxx=mpicxx --with-fc=mpif90 \
            --with-blaslapack-lib=/shared/apps/openblas/lib/libopenblas.so \
            --with-scalapack-dir=/shared/apps/scalapack \
            --with-hdf5-dir=/shared/apps/hdf5 \
            --download-metis --download-parmetis
make all && make install

4.2 Milestone 2: Lmod Environment Modulefiles (Lab 4)

Each compiled library must have a clean, declarative Lua modulefile placed inside /shared/modulefiles/<package>/<version>.lua. Users must be able to load any library on demand via module load <package> without manual environment variable pollution:

  • /shared/modulefiles/openblas/0.3.26.lua: Prepends PATH, LD_LIBRARY_PATH, C_INCLUDE_PATH, and sets OPENBLAS_DIR.
  • /shared/modulefiles/fftw3/3.3.10.lua: Prepends binary, library, and header paths; sets FFTW_DIR.
  • /shared/modulefiles/hdf5/1.14.3.lua: Prepends HDF5 compiler wrappers, shared libraries, and headers; sets HDF5_DIR.
  • /shared/modulefiles/scalapack/2.2.0.lua: Prepends ScaLAPACK library and header paths; sets SCALAPACK_DIR.
  • /shared/modulefiles/petsc/3.20.5.lua: Prepends PETSc paths and sets PETSC_DIR.
Verifying Lmod on Compute Nodes

# fftw3/3.3.10  hdf5/1.14.3  openblas/0.3.26  petsc/3.20.5  python-hpc/1.0  scalapack/2.2.0

4.3 Milestone 3: Centralized Python Environment & mpi4python (Lab 4)

Rather than isolated, unlinked user Python installations, students must establish a cluster-wide shared virtual environment under /shared/apps/python-hpc-env:

  1. Instantiate the virtual environment on master: python3 -m venv /shared/apps/python-hpc-env.
  2. Create site.cfg instructing pip to link NumPy directly against your compiled OpenBLAS (/shared/apps/openblas/lib).
  3. Compile NumPy from source using pip install --no-binary :all: numpy==1.26.4.
  4. Install SciPy and mpi4python (mpi4py), ensuring mpi4py builds with your Open MPI headers.
  5. Deploy modulefile /shared/modulefiles/python-hpc/1.0.lua configuring VIRTUAL_ENV, PYTHONPATH, PATH, and LD_LIBRARY_PATH.
  6. Verify linkage on compute nodes using python3 -c "import numpy; numpy.show_config()" and a multi-node mpi4py test script.

4.4 Milestone 4: Cluster Benchmarking & Tuning (Lab 6)

To evaluate the real sustained performance of your cluster, your group must compile and tune High-Performance Linpack (HPL):

  1. Compile HPL: Download HPL 2.3, configure Make.Rocky pointing to /shared/apps/openblas and Open MPI wrappers, compile xhpl, and place it in /shared/benchmarks/hpl/.
  2. Tune HPL.dat:
    • Problem Size (N): Calculate N to consume approximately 80% of aggregate compute node RAM without inducing kernel disk swapping (e.g., N ≈ 25,000).
    • Block Size (NB): Set to optimal cache blocking factor (e.g., NB = 128).
    • Process Grid (P × Q): Match total allocated MPI tasks across 4 nodes × 2 tasks = 8 ranks (e.g., P=2, Q=4).
  3. Execute via Slurm: Submit submit_hpl.sh via sbatch allocating all 4 compute nodes.
  4. Analyze Metrics:
    • Calculate theoretical peak performance (Rpeak = Nodes × CPUs × GHz × FLOPs/Cycle).
    • Extract sustained benchmark score (Rmax in GFLOPS) from hpl_result_*.out.
    • Calculate cluster computational efficiency: E = (Rmax / Rpeak) × 100%.

4.5 Milestone 5: Distributed MPI Programming Mastery (Chapter 8 Workbook)

Your team must be intimately familiar with the foundational MPI primitives covered in the Chapter 8 Workbook, as they form the theoretical and practical basis of the demonstration challenge:

  • Point-to-Point Messaging: MPI_Send() and MPI_Recv() with explicit buffer lengths, data types, rank identifiers, and message tags. Understanding deadlock avoidance.
  • Process Identification & Synchronization: MPI_Comm_rank(), MPI_Comm_size(), MPI_Get_processor_name(), and barrier synchronization via MPI_Barrier().
  • Collective Communication:
    • MPI_Bcast(): One-to-all broadcast of configuration values or parameters.
    • MPI_Scatter(): One-to-all distribution of segmented arrays across worker ranks.
    • MPI_Gather(): All-to-one collection of local results into an aggregate array on root.
    • MPI_Allgather(): All-to-all gathering where every participating rank receives the full aggregated dataset (no root argument).
  • Parallel Reductions: MPI_Reduce() using collective reduction operators (MPI_SUM, MPI_MIN, MPI_MAX, MPI_PROD).
  • End-to-End Application: The multi-stage Distributed Weather Analysis program synthesizing all primitives into a complete processing pipeline.

5. Live Demonstration Protocol & The "On-the-Fly" Challenge

Each pair of students will demonstrate their cluster live to the course lecturer during their assigned evaluation slot. The demonstration follows a rigorous three-phase protocol:

Phase 1: Cluster Health & Scientific Stack Audit (20 Mins)

The lecturer inspects live cluster status: sinfo showing 4 idle compute nodes, shared NFS mounts, and checks that module use /shared/modulefiles exposes all five scientific modules and the Python environment. The group displays clean HPL benchmark output (xhpl GFLOPS, Rpeak, Rmax, and efficiency calculation).

Phase 2: The Live "On-The-Fly" Algorithm Challenge (25 Mins)

During the demo, the lecturer will supply an unannounced source code file or computational problem. It will require one or more of your installed libraries:

  • An OpenBLAS matrix computation (e.g., parallel DGEMM / matrix-matrix multiplication).
  • An FFTW 3 multi-dimensional distributed Fourier transform.
  • A Parallel HDF5 dataset write/read test exercising parallel MPI-IO chunks across worker nodes.
  • A ScaLAPACK distributed linear equation solver (e.g., Ax = b across a process grid).
  • A PETSc parallel Krylov subspace linear solver / Poisson equation on a distributed grid.
  • A Python / mpi4py distributed pipeline using NumPy arrays linked to OpenBLAS.
  • An MPI Collective Algorithm (e.g., parallel reduction, scatter-gather data partitioning, or Monte Carlo estimation).

Student Actions Required: Your pair must save the file to /shared/, load the corresponding Lmod module(s), compile the code with correct wrapper flags (or execute within python-hpc-env), submit it across all 4 compute nodes via Slurm (srun or sbatch), and explain the output and data flow to the lecturer.

Phase 3: Individual Oral Defense (15 Mins)

The lecturer examines each student individually on compiler flags, dynamic library linking (LD_LIBRARY_PATH), Lmod mechanics, MPI collective communication complexity, and benchmarking analysis to ensure equal technical contribution.
