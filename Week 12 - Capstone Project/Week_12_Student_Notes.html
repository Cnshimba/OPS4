1. Capstone Architecture Overview

The Capstone Project brings together all 12 weeks of High Performance Computing concepts into a production-grade automated deployment. Rather than manually configuring nodes, students write declarative infrastructure code to launch a 5-node cluster (1 Master Controller Node + 4 Compute Worker Nodes).

2. MapReduce & Data Parallelism

In addition to traditional message passing (MPI), data-intensive parallel workloads utilize the MapReduce paradigm to process massive datasets across distributed nodes.

  • Map Stage: Master node breaks input data into independent key-value chunks processed in parallel across worker nodes.
  • Shuffle / Sort Stage: Intermediate data is grouped by key across the private network.
  • Reduce Stage: Worker nodes aggregate grouped intermediate values into final output results.

3. Fault Tolerance & Checkpointing

When running long-duration simulations across multi-node clusters, hardware Mean Time Between Failures (MTBF) drops significantly. Checkpointing periodically saves execution state to non-volatile storage:

4. The Exascale Horizon & Beyond

Exascale supercomputing ($> 10^{18}$ FLOPS) presents three major engineering challenges: Power Efficiency ($< 20 \text{ MW}$ power envelopes), Memory Bandwidth (HBM3/CXL interconnects), and Heterogeneous Hardware Acceleration.

5. Capstone Project Architecture Verification Checklist

  1. Provisioning: Deploy 5-node cluster via automated Vagrantfile on subnet 192.168.57.0/24.
  2. Orchestration: Configure Slurm Workload Manager queues across nodes (slurmctld, slurmd).
  3. Software Stack: Build Lmod environment modules with OpenBLAS, FFTW3, HDF5, ScaLAPACK, and mpi4py.
  4. Telemetry: Setup Prometheus scraping Node Exporter with a Grafana dashboard.
  5. Verification: Submit a multi-node parallel job via Slurm srun -N4 hostname and verify execution.
