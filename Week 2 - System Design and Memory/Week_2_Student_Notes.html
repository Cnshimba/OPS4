1. Cluster Organization

1.1 The Beowulf Revolution

Supercomputing was historically dominated by exotic, multimillion-dollar proprietary mainframes built by Cray or IBM. In 1994, NASA researchers Thomas Sterling and Donald Becker transformed parallel computing by constructing Beowulf — a 16-node cluster built entirely from mass-market, commodity off-the-shelf (COTS) PCs connected over standard Ethernet using Linux.

1.2 Anatomy of a Beowulf Cluster

Modern enterprise HPC clusters use a strictly tiered node layout to isolate high-throughput compute traffic from external administrative networks.

Figure 1: Standard Beowulf Architecture — separating public access from private compute interconnects.

🖥️ Login Node (Master/Head)

The front entry point. Users log in via SSH to edit code and submit Slurm job scripts. Heavy computational tasks are strictly forbidden on the login node.

⚡ Compute Nodes

High-density workhorse servers sitting in server racks, executing parallel MPI and OpenMP tasks in isolated environments without direct public internet exposure.

🌐 High-Speed Interconnect

Dedicated low-latency fabric (InfiniBand or 100GbE RoCE) enabling low-overhead inter-node message passing between compute processes.

💾 Storage Node

Enterprise shared storage exporting NFS or parallel filesystems (Lustre/BeeGFS) so all compute nodes access a unified home directory.

1.3 Symmetric Multi-Processing (SMP) vs NUMA

Individual multi-socket compute nodes operate as Symmetric Multi-Processing (SMP) machines where multiple CPU sockets share a common physical RAM space. However, due to memory bus limitations, modern multi-socket servers use a Non-Uniform Memory Access (NUMA) architecture.

💡 NUMA Performance Implication

In a NUMA system, a CPU accesses memory attached to its local memory controller significantly faster than memory attached to a remote CPU socket. Unaligned threads incur cross-socket interconnect penalties.

2. Interconnect Topologies

2.1 Latency vs Bandwidth

Cluster interconnect networks are evaluated along two primary performance dimensions:

  • Bandwidth: The data transfer capacity across the channel (e.g., 200 Gbps HDR InfiniBand). Crucial for bulk data transfers and checkpointing.
  • Latency: The round-trip time required to transmit a minimal packet from sender to receiver (e.g., 0.6 microseconds). Critical for fine-grained MPI message synchronization.

3. The OpenHPC Software Stack

Deploying a production HPC cluster requires a cohesive software ecosystem. OpenHPC provides a standardized, community-driven repository of pre-packaged HPC components.

1. Provisioning Layer: Warewulf

Warewulf manages stateless node images (VNFS). Compute nodes boot directly over the network via PXE/iPXE, loading OS images into RAM.

2. Resource Manager: Slurm

Slurm orchestrates workload queues, allocates compute nodes to jobs, and enforces resource isolation using Linux cgroups.

3. User Environment: Lmod Modules

Lmod environment modules allow users to load dynamic toolchains (e.g. module load gcc/12.2 openmpi/4.1.4) without breaking default environment paths.
