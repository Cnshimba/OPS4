Section 1: Creating the HPC Infrastructure Using Vagrant

1.1 Learning Outcomes & Required Resources

By completing this laboratory section, students will achieve the following practical outcomes:

  1. Install and configure a Vagrant environment successfully on the host machine.
  2. Understand and analyze the structured syntax of a multi-node Vagrantfile specification.
  3. Explain the core concepts of Infrastructure as Code (IaC) and declarative environments.
  4. Deploy five Rocky Linux 9.6 virtual systems connected via an isolated private virtual network.
  5. Apply VirtualBox performance optimizations specifically tailored for parallelized cluster simulations.

To successfully perform this lab, ensure access to the following hardware and software resources:

  • Host System: Ubuntu 24.04 / 26.04 LTS or Windows 11 / 10 Workstation.
  • Hypervisor: Oracle VM VirtualBox 7.x installed on the host system.
  • Orchestrator: HashiCorp Vagrant package installer and CLI binaries.
  • Base Image: Certified Bento Rocky Linux 9.6 Base Box (v202510.26.0).

1.4 Step 3 – Structure of the Cluster Vagrantfile

Replace the default generated text inside your Vagrantfile with the complete cluster deployment script below. This defines 1 master control node (4GB RAM, 2 CPUs) and 4 dedicated compute worker nodes (2GB RAM, 2 CPUs each) connected over private subnet 192.168.56.0/24:

Vagrantfile — Ruby Cluster Specification
Terminal Command 
# -*- mode: ruby -*-
# vi: set ft=ruby :

Vagrant.configure("2") do |config|
  # Base Box Specification
  config.vm.box = "bento/rockylinux-9.6"
  config.vm.box_version = "202510.26.0"
  config.ssh.insert_key = false
  config.vm.synced_folder ".", "/vagrant", disabled: true

  # Global VirtualBox Performance Settings
  config.vm.provider "virtualbox" do |vb|
    vb.gui = false
    vb.customize ["modifyvm", :id, "--hwvirtex", "on"]
    vb.customize ["modifyvm", :id, "--nestedpaging", "on"]
    vb.customize ["modifyvm", :id, "--largepages", "on"]
    vb.customize ["modifyvm", :id, "--paravirtprovider", "kvm"]
    vb.customize ["modifyvm", :id, "--nictype1", "virtio"]
    vb.customize ["modifyvm", :id, "--nictype2", "virtio"]
    vb.customize ["modifyvm", :id, "--audio-enabled", "off"]
    vb.customize ["modifyvm", :id, "--usb", "off"]
    vb.customize ["modifyvm", :id, "--clipboard-mode", "disabled"]
    vb.customize ["modifyvm", :id, "--draganddrop", "disabled"]
    vb.customize ["modifyvm", :id, "--rtcuseutc", "on"]
  end

  # Master Control Node (4096MB Memory, 2 CPUs)
  config.vm.define "master" do |master|
    master.vm.network "private_network", ip: "192.168.56.10"
    master.vm.provider "virtualbox" do |vb|
      vb.name = "HPC-Master"
      vb.memory = 4096
      vb.cpus = 2
    end
  end

  # Compute Worker Nodes (2048MB Memory, 2 CPUs each)
  (1..4).each do |i|
    config.vm.define "compute0#{i}" do |node|
      node.vm.network "private_network", ip: "192.168.56.1#{i}"
      node.vm.provider "virtualbox" do |vb|
        vb.name = "HPC-Compute0#{i}"
        vb.memory = 2048
        vb.cpus = 2
      end
    end
  end
end

1.5 Step 4 – VirtualBox Performance Optimizations for HPC Workloads

To maximize parallel cluster simulation capabilities on resource-constrained host machines, specific advanced hypervisor acceleration parameters are declared in the provider block:

VirtualBox ParameterHPC System Performance ImpactImportance
vb.gui = falseLaunches VMs in background headless mode to free host RAM and GPU resources.Essential
--hwvirtex / --nestedpaging onEnables hardware-assisted CPU/memory translations for native-speed execution.Essential
--largepages onUses larger page allocations to prevent translation lookaside buffer (TLB) cache misses during load.Recommended
--paravirtprovider kvmAttaches a KVM acceleration module to streamline guest OS virtualization routines.Essential
--nictype1/2 virtioAttaches paravirtualized network adapters instead of heavier emulated hardware drivers.Essential

Section 2: Preparing the Infrastructure for an HPC Cluster

Once your virtual cluster environments have been provisioned by Vagrant, they must undergo extensive standard Linux system-level preparation before installing Slurm workload orchestrators. This section guides you through setting up hostnames, Chrony time sync, restrictive NFS shares, passwordless SSH keys, Munge keys, and pdsh/pdcp parallel tools.

2.1 Learning Outcomes

  • Formulate secure private hostnames across Rocky Linux cluster nodes.
  • Implement precise local name resolution lists bypassing public DNS latency.
  • Synchronize internal system timers across distributed compute units via Chrony.
  • Export and mount secure multi-host private NFS networks protected with restrictive firewalls.
  • Setup passwordless SSH keys to streamline remote task distribution and scheduler control.
  • Install and test Munge cryptographic validation routines for secure job payload routing.
  • Administer parallel administrative tool chains using pdsh and pdcp.

2.6 Formulating Restrictive Multi-Host NFS Shares

An NFS share enables nodes to share binaries, configurations, and cluster logs. Configure firewalld rich rules restricting NFS traffic strictly to subnet 192.168.56.0/24.

Step 1: NFS Server Deployment (Master Node)

NFS Master Server Configuration
Terminal Command 
sudo dnf install -y nfs-utils
sudo mkdir /shared
sudo chmod 777 /shared

# Append export rule in /etc/exports
echo "/shared 192.168.56.0/24(rw,sync,no_root_squash)" | sudo tee -a /etc/exports

Step 2: Enable Services & Firewalld Rich Rules

Firewalld Rich Rules Setup
Terminal Command 
sudo systemctl enable --now nfs-server
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.56.0/24" service name="nfs" accept'
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.56.0/24" service name="mountd" accept'
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.56.0/24" service name="rpc-bind" accept'
sudo firewall-cmd --reload
sudo firewall-cmd --list-rich-rules
sudo exportfs -rav

Step 3: Mount and Verify (All Compute Nodes)

NFS Client Mount
Terminal Command 
sudo dnf install -y nfs-utils
sudo mkdir /shared
sudo mount master:/shared /shared
df -h | grep /shared

2.8 Installing and Activating Munge Cryptographic Keys

Munge provides secure authentication payload signing across distributed cluster nodes. Deploy EPEL, generate the secret key, and execute the automated loop script across worker nodes:

Master Munge Key Generation
Terminal Command 
sudo dnf install -y epel-release
sudo dnf install -y munge munge-libs
sudo create-munge-key

Distribute and enforce strict mode 400 key permissions across worker nodes using the following deployment script loop:

Automated Munge Distribution Loop
Terminal Command 
for node in compute01 compute02 compute03 compute04
do
  echo "Configuring Munge key on ${node}..."
  sudo cp /etc/munge/munge.key /tmp/
  sudo chmod 644 /tmp/munge.key
  scp /tmp/munge.key ${node}:/tmp/
  ssh ${node} <<'EOF'
    sudo mv /tmp/munge.key /etc/munge/munge.key
    sudo chown munge:munge /etc/munge/munge.key
    sudo chmod 400 /etc/munge/munge.key
    sudo systemctl enable --now munge
EOF
done

Verify Munge cryptographic authentication on master:

Munge Verification Test
Terminal Command 
sudo systemctl enable --now munge
munge -n | unmunge

2.9 Cluster Administration and Parallel File Copying with pdsh and pdcp

Parallel Distributed Shell (pdsh) spawns parallel SSH connections to target compute hosts concurrently, cutting cluster task execution time from minutes to seconds.

Installing pdsh Modules
Terminal Command 
sudo dnf install -y pdsh-rcmd-ssh pdsh-mod-dshgroup pdsh-mod-genders

# Set SSH as default transport type in bash profile
export PDSH_RCMD_TYPE=ssh
echo 'export PDSH_RCMD_TYPE=ssh' >> ~/.bashrc
source ~/.bashrc

Creating DSH Groups & Executing Concurrently

Configuring /etc/dsh/group/compute
Terminal Command 
sudo mkdir -p /etc/dsh/group
sudo tee /etc/dsh/group/compute <<EOF
compute01
compute02
compute03
compute04
EOF

# Execute parallel health diagnostics across all compute nodes
pdsh -g compute hostname
pdsh -g compute uptime
pdsh -g compute free -h
pdsh -g compute df -h

Parallel File Transfers with pdcp

Create default machine list /etc/pdsh/machines and copy files concurrently:

pdcp Machine List & File Transfer
Terminal Command 
sudo mkdir -p /etc/pdsh
sudo tee /etc/pdsh/machines <<EOF
compute01
compute02
compute03
compute04
EOF

# Distribute file in parallel to all machines (-a)
pdcp -a /tmp/munge.key /tmp/
pdsh -a "ls -l /tmp/munge.key"

Firewall Configuration for Slurm Scheduler (Port 6818)

Port 6818 Firewall Rules via pdsh
Terminal Command 
pdsh -R ssh -g compute "sudo firewall-cmd --permanent --add-rich-rule='rule family=\"ipv4\" source address=\"192.168.56.0/24\" port protocol=\"tcp\" port=\"6818\" accept'"
pdsh -R ssh -g compute "sudo firewall-cmd --reload"
nc -zv compute01 6818

Appendix A: System Troubleshooting Reference Guide

Review diagnostic procedures for standard system errors encountered during this lab setup:

Error SymptomLikely Core CauseResolution Step Action
NFS Mount operation hangs or timeouts Master firewall blocking NFS/RPC services. Ensure nfs, mountd, and rpc-bind rich rules are loaded inside firewalld, then reload.
SSH requests standard password Public keys were not appended to authorized_keys. Re-run ssh-copy-id <node> from the master node to register your ED25519 key.
Munge credential validation fails Different key files or incorrect file permissions. Ensure munge.key ownership is munge:munge and mode is set strictly to 400.
Host network name unresolved Incorrect /etc/hosts listings. Re-examine /etc/hosts on every VM and insert correct IP address bindings.
Cluster timers out of sync Chrony service disabled or blocked. Execute sudo systemctl enable --now chronyd and check with chronyc tracking.
