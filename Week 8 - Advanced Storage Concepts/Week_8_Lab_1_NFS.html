📋 Combined Laboratory Overview

Evaluating and observing HPC cluster performance requires a integrated two-phase workflow:
Phase 1: Visual Telemetry Pipeline — Deploying Prometheus and Node Exporters to collect metrics and Grafana to visualize cluster load in real-time.
Phase 2: Benchmark Execution & Profiling — Compiling and configuring the High-Performance Linpack (HPL) benchmark, executing it across all nodes via Slurm, and analyzing real-time CPU spikes, memory saturation, and sustained GFLOPS ($R_{max}$) in Grafana.

Section 1: Architectural Foundations

1.1 Benchmarking Metrics ($R_{peak}$ vs $R_{max}$)

MetricDefinitionSignificance
Rpeak (Theoretical Peak)The maximum mathematical performance calculated from CPU cores, clock speed, and execution instructions per cycle.Upper limit — never achievable in practice
Rmax (Sustained Performance)The actual measured floating-point performance (GFLOPS) achieved when solving a dense linear system with HPL.Real-world Top 500 performance metric
Cluster Efficiency (E)$E = (R_{max} / R_{peak}) \times 100\%$Measures memory bandwidth efficiency, network latency, and compiler tuning

Section 5: HPL Matrix Tuning & Slurm Execution

Step 1 – Sizing Problem Size N (80% Memory Rule)

Terminal
Terminal Command 
Memory (GB) = (N² × 8 bytes/double) / 1024³

For ~6 GB total active RAM across 4 compute nodes:
N = sqrt( (6.0 × 1024³ × 0.80) / 8 ) ≈ 25000

Step 3 – Create Submission Script and Run via Slurm

Terminal
Terminal Command

#!/bin/bash
#SBATCH --job-name=HPL_Benchmark
#SBATCH --output=hpl_result_%j.out

EOF

Extracting GFLOPS and Calculating Cluster Efficiency

Terminal
Terminal Command 
cat hpl_result_*.out | grep -A 5 "T/V"
Terminal
Terminal Command 
================================================================================
T/V                N    NB     P     Q               Time             Gflops
--------------------------------------------------------------------------------
WR11C2R4       25000   128     2     4             112.54             1.163e+01
================================================================================
Terminal
Terminal Command 
Rpeak = 4 nodes × 2 CPUs × 2.4 GHz × 4 FLOPs/cycle = 76.8 GFLOPS
Efficiency (E) = (Rmax / Rpeak) × 100% = (11.63 / 76.8) × 100% = 15.14%

Section 7: Troubleshooting Reference

SymptomPossible CauseResolution
Node shows 'DOWN' in PrometheusNode Exporter crashed or firewalld blocking port 9100.Run systemctl status node_exporter; check firewall-cmd --list-rich-rules.
HPL job crashes with OOM-killProblem size N is too high, exceeding available RAM.Decrease N in HPL.dat (e.g., to 18000) to ensure memory fits in physical RAM.
Grid P × Q mismatch errorProcess grid in HPL.dat doesn't match Slurm tasks.Ensure P × Q (e.g., 2 × 4 = 8) matches nodes × tasks-per-node (4 × 2 = 8).
