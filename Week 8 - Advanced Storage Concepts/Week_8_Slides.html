Week 8 Slides: Advanced Storage Concepts

Slide 1: Storage Taxonomy

  • Block (SAN): Raw disk access (iSCSI, FC). Used for Booting OS, Databases.
  • File (NAS): Shared folders (NFS, SMB). Used for Home Directories.
  • Object (Cloud): ID-based access (S3). Used for Massive Archival.

Slide 2: The HPC Storage Hierarchy

  • Tier 1: Burst Buffer (NVMe):
    • Extreme Speed (>100GB/s). Low Capacity.
  • Tier 2: Parallel Scratch (BeeGFS/Lustre):
    • High Bandwidth. Petabyte Capacity. Work happens here.
  • Tier 3: Home Area (NFS):
    • Scripts/Code. Convenience over Speed.

Slide 3: Network File System (NFS)

  • Architecture: Single Server exports directory -> Many Clients mount it.
  • The Bottleneck: IOPS limited by the single server's disk head. Bandwidth limited by one network cable.
  • Use Case: /home directories, configuration files. NOT for heavy simulation I/O.

Slide 4: Parallel File Systems (Concepts)

  • Solution: Don't use one huge server. Use 100 small ones.
  • Metadata Separation: "Where is the file?" (Metadata) is stored separately from "What is in the file?" (Data).
  • Striping: A single 10GB file is chopped into 4MB chunks and spread across 10 servers.
    • Read Speed = Sum of 10 servers.

Slide 5: Parallel FS Examples

  • BeeGFS:
    • Easy to manage.
    • Mgmtd: Cluster Membership.
    • Meta: Directory Structure.
    • Storage: Raw Data.
  • Lustre:
    • The Grandfather of HPC storage.
    • Powering 60% of Top100.
    • Terminology: MGS (Management), MDS (Metadata), OSS (Storage).

Slide 6: Benchmarking

  • IOR (Interleaved or Random): Measures Bandwidth (GB/s).
  • mdtest: Measures Metadata Performance (IOPS - Operations Per Second).
  • The Rule: You cannot tune what you cannot measure.

Slide 7: Lab Overview

  • Part 1: Deploy NFS for /home.
  • Part 2: Deploy BeeGFS for /scratch (Converged Architecture).
